# Writing a requirement template

A template is one JSON file that describes a major's checklist. BearPlan reads it and builds the requirements grid, the drop rules, the progress numbers and the "What's left" list from it. No code changes are needed to add a major.

The CS template in [`src/templates/cs-engineering-fa24.json`](../src/templates/cs-engineering-fa24.json) uses every feature below, so it is the best example to copy.

## Two ways to add one

- **Just for you:** in the app, open Plan settings (gear icon) and choose **Import requirement template**, or use **Import a checklist JSON…** during setup. It is saved in your browser.
- **For everyone:** add the file to `src/templates/`, add it to `BUILT_IN_TEMPLATES` in `src/lib/store.svelte.ts` (majors and minors share that list), and open a pull request. Link the official checklist or handbook page in the PR.

## Top level

```json
{
  "id": "info-cals-fa25",
  "name": "Information Science",
  "college": "CALS",
  "matriculatedFrom": "FA25",
  "totalCredits": 120,
  "totalCreditsNote": "120 cr minimum. Confirm with your advisor.",
  "filters": [{ "id": "college", "label": "College", "icon": "book" }],
  "repeatableCodes": ["INFO 4900"],
  "failingGrades": ["S", "SX", "U", "UX", "D+", "D", "D-", "F"],
  "sections": [],
  "checks": []
}
```

| Field | Meaning |
|---|---|
| `id` | Unique, no spaces. Saved plans point at it, so don't change it once people use it. |
| `matriculatedFrom` | First entry term the checklist applies to, like `FA24`. |
| `matriculatedBefore` | Optional. First entry term the checklist no longer applies to, when a newer one replaces it. |
| `totalCredits` | Optional. Shown as "88 / 120 cr". Leave it out if you don't know it. |
| `filters` | The filter pills above the grid. Each section names one with its `filter` field. |
| `repeatableCodes` | Courses allowed more than once (research, independent study, team projects). Everything else is "no course may be used twice". Students can also mark any course repeatable from the placing banner; that list is saved in their plan, not the template. |
| `failingGrades` | Grades that get a warning in sections marked `letterGrade`. |
| `draft` | `true` for templates generated by `scripts/import-catalog.mjs` and not checked by a person. The app shows a warning with a link to `source`. |
| `source` | Optional `https://` link to the official requirements page. |
| `footnote` | Optional text under the checklist, like grade rules. |
| `concentrations`, `maxConcentrations` | Optional extra sections a plan opts into. See [Concentrations](#concentrations). |

## Sections

```json
{
  "id": "core",
  "title": "CS Core",
  "column": "right",
  "filter": "core",
  "icon": "code",
  "note": "Shown under the title.",
  "leftLabel": "Core",
  "type": "slots",
  "letterGrade": true,
  "slots": [{ "id": "c1", "label": "CS 2800 / 2802", "rule": [{ "codes": ["CS 2800", "CS 2802"] }] }]
}
```

- `type: "slots"`: fixed rows, one course each, with a `slots` list. Rows can carry an `option` label ("Option 1", "Option 2") for alternatives: rows without an option are always required, and the section is done when one option's rows are all filled. Progress counts the option with the most filled rows (then the fewest open).
- `type: "creditBucket"`: any number of courses until `minCredits` is reached. The `rule` on the section applies to every course in it.
- `column` is `left` or `right` for the "All" view.
- `icon` is one of `pen`, `book`, `flask`, `sigma`, `code`, `star`, `run`, `plus`.
- `leftLabel` is the short name in "What's left". It defaults to the title.
- `letterGrade: true` flags S/U and failing grades in the section. `suAllowedCodes` lists courses that may still be taken S/U there, like research credit (an S passes; a U is still flagged).
- `swimTest: true` adds the swim test checkbox, and `spcl: true` adds the area-name field.
- `excludeFromCredits: true` keeps the section's credits out of the degree total (PE).

## Rules

A `rule` is a list of matches. A course fits if it satisfies **any** match, and a match passes only if **all** its fields hold.

| Field | Example | Passes when |
|---|---|---|
| `codes` | `["MATH 1910"]` | The code is in the list. |
| `subjects` | `["ENGRD"]` | The subject is in the list. |
| `excludeSubjects` | `["CS"]` | The subject is not in the list. |
| `excludeCodes` | `["CS 4090"]` | The code is not in the list. |
| `minLevel` / `maxLevel` | `3000` | The catalog number is at least / at most this. |
| `minCredits` | `3` | The course has at least this many credits. |
| `numberPattern` | `["4xx1"]` | The number fits a pattern, where `x` is any digit. |
| `excludeNumberPattern` | `["10xx"]` | The number fits none of the patterns. |
| `distributions` | `["CA", "SCD-HA"]` | The course has one of these distribution categories. `CA` matches `CA-AG` and `CA-AS`; a category with a dash matches only itself. |
| `reason` | `"Not a writing seminar"` | Replaces the generated refusal message. |

Two examples from the CS template:

```json
"rule": [
  { "subjects": ["CS"], "minLevel": 4000, "minCredits": 3, "excludeCodes": ["CS 4090"] },
  { "codes": ["CS 3700", "CS 3780"] }
]
```

A CS elective is either non-excluded CS 4000+ with 3+ credits, or CS 3700/3780.

```json
"rule": [
  { "excludeSubjects": ["PE", "AIRS", "MILS", "NAVS"], "excludeNumberPattern": ["10xx"] },
  { "subjects": ["AIRS", "MILS", "NAVS"], "minLevel": 3000 }
]
```

Anything except PE, 10xx courses and ROTC, plus ROTC at 3000 and above.

## Section constraints

Constraints check a whole section. They show as chips under the title, and unmet ones appear in "What's left".

| Type | Fields | Example |
|---|---|---|
| `minCredits` | `credits` | Liberal Studies needs 18 credits. |
| `minCount` | `count`, `match` | At least 2 courses with `{ "minLevel": 2000 }`. |
| `maxCount` | `count`, `match`, `reason` | At most one 2000-level technical elective. Drops that would break it are refused with `reason`. |
| `maxCredits` | `credits`, `match`, `reason` | At most 12 credits of research. Like `maxCount`, but on credits. |
| `minGroups` | `count` | Courses from at least 3 groups. |
| `groupMinCredits` | `group`, `credits` | One course of at least 3 credits in Group 7. |
| `groupCredits` | `group`, `credits` | At least 7 credits in total from Group A. |
| `groupMaxCount` | `group`, `count` | At most 2 courses from Group 6. |

Group constraints need a `groups` list on the section. Each group has an `id`, a `name`, and `categories` and/or `codes`. A course that fits several groups is assigned to one automatically, picking the assignment that meets the most constraints.

## Plan-wide checks

Checks are requirements that are not rows. They read every course in the plan, wherever it sits, so a course can fill a major row and still meet a check. That is how college distributions that may overlap with the major work.

```json
{
  "id": "probability",
  "title": "Probability",
  "codes": ["BTRY 3080", "ECON 3130"],
  "metText": "satisfied by {code}",
  "missText": "not yet. Needs an accepted probability course."
}
```

| Field | Meaning |
|---|---|
| `codes` | A course counts if its code is listed. |
| `match` | Or if it passes any of these matches (same fields as a `rule`). A check needs `codes`, `match`, or both. |
| `count` | Courses needed. Defaults to 1. |
| `credits` | Credits needed instead of a course count. |
| `section` | Only courses placed in this section count, for a check that is part of one requirement (ILR's QP, ICL and LH inside the in-college electives). |
| `group` | Checks with the same group can't use the same course, for rules like "a course may fulfill only one distribution". Checks claim courses in file order, so list the narrow ones first. |
| `metText` / `missText` | `{code}` in `metText` becomes the courses used. When a counted check is partly met, the app shows progress like "3 / 9 cr so far (WRIT 1370)," before `missText`. |

A CALS distribution as a check:

```json
{
  "id": "psc",
  "title": "Physical Sciences",
  "match": [{ "distributions": ["PSC"], "minCredits": 3 }],
  "group": "cals",
  "metText": "satisfied by {code}",
  "missText": "needs one PSC-AG course of 3+ credits."
}
```

## Concentrations

A template can offer optional concentrations. Each one is a list of extra sections that appear only in plans that pick it during setup or in plan details.

```json
"maxConcentrations": 2,
"concentrations": [
  { "id": "finance", "name": "Finance", "sections": [ { "id": "fin-req", "title": "Finance: Required", ... } ] }
]
```

- `maxConcentrations` is how many a plan may pick. It defaults to 1.
- Section ids must be unique across the template and every concentration, since a plan can combine them.
- Dropping a concentration moves its courses to Additional Space.

## Minors

A minor is a template with `"kind": "minor"`. Students add it to a plan next to their major checklist, during setup or in plan details.

```json
{
  "id": "business-minor",
  "kind": "minor",
  "name": "Business",
  "college": "SC Johnson College of Business",
  "matriculatedFrom": "FA22",
  "minUniqueCredits": 12,
  "filters": [],
  "sections": [ ... ],
  "checks": [ ... ]
}
```

- Sections and checks use the same format as a major's. The app prefixes their ids with the minor's id, so they can't collide with the major's, and gives the minor its own filter pill.
- A minor's checks only count courses placed in that minor.
- A course can sit in one major row and one minor row at the same time. It counts once toward the degree credit total.
- `minUniqueCredits` is how many of the minor's credits must not also count toward the major, the usual Cornell "unique credits" rule. The app shows it as a check.
- A minor can't set `totalCredits` or `concentrations`.

## Distribution categories

Course categories come from the Class Roster API (`crseAttrs` entries marked `DistReq`), e.g. `SBA-AG`, `ALC-AS`, `SCD-AS`. The fetch script also adds `FWS` to every First-Year Writing Seminar, since the API marks those only by an "FWS:" title. Search a course in the app and drag it onto a distribution row to see what it carries; a refused drop lists the course's categories.

## Checking your file

Import it in the app. If the shape is wrong, the import lists each problem, like `sections[2].column must be "left" or "right"`. Once it loads, try dropping a few courses that should and should not fit.
